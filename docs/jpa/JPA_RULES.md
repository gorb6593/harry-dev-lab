# JPA_RULES.md

작성일: 2026-03-04

## 목적
이 문서는 JPA 학습과 구현 시 반드시 지켜야 하는 기준이다.
목표는 "작동하는 코드"가 아니라 "10년 이상 경력 시니어도 방어 가능한 코드"를 만드는 것이다.

## 공식 기준
- Jakarta Persistence를 기준 개념으로 삼는다.
- Spring Data JPA는 편의 레이어일 뿐, 내부 원리는 JPA/EntityManager 관점에서 설명할 수 있어야 한다.
- 공식 참고:
  - [Jakarta Persistence](https://jakarta.ee/specifications/persistence/)
  - [Jakarta Persistence 3.2](https://jakarta.ee/specifications/persistence/3.2/)
  - [Jakarta EE](https://jakarta.ee/)

## 절대 원칙
1. 엔티티는 API 응답 모델이 아니다.
- Controller에서 엔티티를 직접 반환하지 않는다.
- 외부 노출은 DTO로 분리한다.

2. 트랜잭션 경계는 서비스 계층에 둔다.
- Controller에 `@Transactional` 금지.
- 복잡한 조회/변경 흐름은 service에서 끝낸다.

3. 기본 Fetch 전략은 명시적으로 관리한다.
- ToOne도 무비판적으로 EAGER 두지 않는다.
- 조회 문제를 매핑으로 숨기지 않는다.

4. 성능 문제는 나중에 보지 않는다.
- N+1 가능성이 있으면 설계 시점부터 기록한다.
- 쿼리 수를 모른 채 완료 처리하지 않는다.

## 엔티티 설계 규칙
1. 엔티티는 식별성과 상태 변경 규칙을 가진다.
- setter 남발 금지.
- 의미 있는 도메인 메서드로 상태를 변경한다.

2. 기본 생성자는 JPA 요구사항을 충족하되 외부 남용을 막는다.
- `protected` 기본 생성자 선호.

3. equals/hashCode는 매우 신중하게 다룬다.
- 학습 초기에 섣불리 구현하지 않는다.
- 구현 시 식별자와 프록시 이슈를 먼저 문서화한다.

4. 양방향 연관관계는 기본값이 아니다.
- 필요한 경우에만 도입한다.
- 도입 시 편의 메서드로 양쪽 객체 상태를 항상 동기화한다.

5. 값 타입은 불변으로 다룬다.
- `@Embeddable`은 mutable하게 만들지 않는다.

## Repository 규칙
1. Repository는 컬렉션처럼 단순하게 보이더라도 SQL 비용을 가진다.
- 호출 1회가 SQL 1회 이상임을 항상 의식한다.

2. 메서드명 쿼리는 단순 조건까지만 허용한다.
- 복잡한 조회는 JPQL/명시 쿼리/전용 조회 계층으로 분리한다.

3. 저장과 조회 관심사를 분리한다.
- 명령(Command)과 조회(Query)를 같은 메서드에 섞지 않는다.

## 트랜잭션 규칙
1. 읽기 전용 조회는 `readOnly = true`를 우선 검토한다.
2. 쓰기 트랜잭션은 최소 범위로 유지한다.
3. 트랜잭션 밖에서 지연 로딩에 의존하지 않는다.
- OSIV가 꺼져 있다는 전제에서 설계한다.

## 연관관계 규칙
1. 연관관계 주인을 정확히 이해하기 전까지 양방향 매핑 확장 금지.
2. 컬렉션 연관관계는 항상 비용을 의식한다.
3. `cascade = ALL`은 습관적으로 쓰지 않는다.
4. `orphanRemoval = true`는 aggregate 경계가 명확할 때만 사용한다.

## 락/동시성 규칙
1. JPA 락은 문제를 정확히 정의한 뒤 도입한다.
- Lost Update인지, 중복 처리인지, 조회 일관성인지 먼저 구분한다.

2. 낙관적 락은 재시도 전략 없이 끝내지 않는다.
3. 비관적 락은 처리량 저하와 데드락 가능성을 함께 문서화한다.
4. 애플리케이션 락/DB 락/Redis 락의 경계를 혼동하지 않는다.

## 금지 목록
1. 엔티티를 그대로 JSON 응답으로 반환
2. 모든 연관관계에 EAGER 사용
3. 의미 없는 public setter 남발
4. Repository 호출 비용을 측정하지 않고 "간단하니까" 승인
5. 연관관계 편의 메서드 없이 양방향 매핑 사용
6. 락 적용 후 트레이드오프 문서화 없이 완료 처리

## 현재 프로젝트 적용 메모
- Java 21 / Spring Boot 3.x 이상 / MySQL 기반 실습
- JPA 학습은 동시성 문제의 DB 락 단계와 직접 연결됨
- 따라서 단순 CRUD보다 "영속성 컨텍스트 / 변경 감지 / Fetch 전략 / 락"을 우선 학습한다
